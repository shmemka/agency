# No Name Agency — кабинет для работы с блогерами

Внутренний сайт агентства: база блогеров, подборки под кампании, согласование с клиентом по ссылке, воронка интеграций, документы и маркировка, задачи, календарь, финансы. У каждого свой кабинет; специалист видит только своих блогеров и свои кампании, учредители видят всё.

**Стек:** React + Vite + Tailwind, база и файлы — Supabase (Postgres, Auth, Storage, Realtime).

## Что внутри

- **Обзор** — сколько интеграций на каждом этапе, мои задачи на сегодня, что требует внимания (блогер молчит три дня, завтра выход без erid, кампания без предоплаты), ближайшие выходы и сроки сдачи статистики в ОРД.
- **Блогеры** — таблица на компьютере, карточки на телефоне. У блогера короткий статус (В базе, Проверенный, Работали, Чёрный список), а этапы переговоров живут в интеграциях и меняются прямо из таблицы. Галочками можно добавить блогеров в подборку кампании или передать другому специалисту.
- **Интеграция** — отдельная панель: дорожка этапов, чек-лист готовности (договор, сценарий, erid, чек, скрин, ОРД), задачи, комментарии, условия, документы. При смене этапа сайт предупреждает, если нет статуса самозанятого или ИП, регистрации в РКН, erid или чека.
- **Кампания** — подборка с ценой блогера и ценой для клиента (наценка считается сама), ссылка для клиента, доска одобренных интеграций по этапам, документы, отчёт, деньги (только учредителям).
- **Страницы для клиента** (`/s/<токен>`, без входа) — подборка с кнопками «Берём» и «Не надо» и отчёт с охватами, CPM, ссылками на выходы и скринами; выгрузка в Excel и PDF. Цена блогера, наценка и контакты туда не попадают: страницу собирает функция базы, которая отдаёт только разрешённые поля.
- **Задачи и календарь** — задачи с исполнителем и сроком, привязанные к блогеру, интеграции или кампании; календарь выходов, задач и сроков ОРД.
- **Финансы** (только учредители) — поступления, выплаты блогерам (собираются из интеграций), расходы, налог 6% или 4%, доход каждого учредителя против лимита самозанятого, настройки ставок.
- **Команда** — доступ, роли, передача блогеров при закрытии доступа.
- **Импорт из Excel** — находит колонки сам (ссылки TikTok и VK, подписчики, охват, цена, пол и возраст аудитории), дубли ищет по всей базе.

## Запуск

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor → New query** и выполните по очереди, каждый файл один раз:
   1. [`supabase/schema.sql`](supabase/schema.sql) — основа;
   2. `seed.sql` — блогеры из ваших таблиц (файла нет в репозитории, в нём контакты и цены; этот шаг можно пропустить);
   3. [`supabase/migrations/002_workspace.sql`](supabase/migrations/002_workspace.sql) — права по ролям, подборки, задачи, финансы. Старые статусы блогеров он сам переносит в интеграции.
3. **Authentication → URL Configuration:** *Site URL* = `https://shmemka.github.io/agency/`, в *Redirect URLs* добавьте `https://shmemka.github.io/agency/**`.
4. **Authentication → Sign In / Providers → Email**: для быстрого старта можно выключить *Confirm email*.
5. **Project Settings → API**: скопируйте *Project URL* и *anon public key*.

Порядок важен: `seed.sql` написан под первую схему, поэтому идёт до миграции. Если база уже работает на первой версии, достаточно выполнить `002_workspace.sql`.

### 2. Сайт на GitHub Pages

GitHub Actions на этом аккаунте сейчас недоступны (GitHub пишет про проблему с оплатой), поэтому сайт собирается командой и выкладывается готовыми файлами в ветку `gh-pages`.

1. Создайте в корне репозитория файл `.env.production` с адресом и ключом из Supabase (Project Settings → API):
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
   Ключ anon public не секретный: он и так виден в браузере любому посетителю сайта, а данные защищают правила доступа в базе. Поэтому файл можно хранить в репозитории.
2. **Settings → Pages → Build and deployment:** Source — **Deploy from a branch**, ветка **gh-pages**, папка **/ (root)**.
3. Выложить сайт: `npm install`, затем `npm run deploy`. Повторять после каждого изменения кода. Сайт откроется по адресу `https://shmemka.github.io/agency/`.

Если GitHub Actions снова заработают, можно публиковать автоматически: в `.github/workflows/pages.yml` верните запуск на push, добавьте ключи в Settings → Secrets and variables → Actions и выберите Source: **GitHub Actions**.

**Свой домен:** Settings → Pages → Custom domain, затем опубликуйте командой `BASE_PATH=/ npm run deploy` (со своим доменом подпапки `/agency/` нет) и поменяйте Site URL в Supabase.

**Приватный репозиторий:** на бесплатном аккаунте GitHub Pages работают только с публичными репозиториями. Чтобы закрыть код, нужен GitHub Pro или перенос сайта на Vercel (`vercel.json` уже лежит в репозитории, переменные те же).

### 3. Первый вход

- Первый, кто зарегистрируется, становится учредителем. Зарегистрируйтесь сами сразу после деплоя.
- Остальные регистрируются по адресу сайта и ждут; учредители получают уведомление и открывают доступ в разделе «Команда». Роль «Учредитель» выдаётся там же.
- На телефоне сайт можно добавить на домашний экран: «Поделиться → На экран Домой».

## Кто что видит

| | Учредитель | Специалист |
| --- | --- | --- |
| Блогеры | все | свои и блогеры своих кампаний |
| Кампании, интеграции, документы | все | где он ответственный или в команде кампании |
| Цена блогера и цена для клиента | да | да |
| Бюджет клиента, финансы, настройки | да | нет |
| Удаление | да | только свои комментарии и задачи |

Права проверяет база (RLS), а не только интерфейс.

## Локальная разработка

```bash
cp .env.example .env   # вписать URL и ключ Supabase
npm install
npm run dev
```

Этапы воронки заданы в `src/lib/constants.ts` и в функции `valid_status` в миграции; правила предупреждений и сроков — в `src/lib/rules.ts`.
