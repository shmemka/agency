# Агентство — кабинет для работы с блогерами

Внутренний сайт агентства: база блогеров, статусы переговоров, интеграции, клиенты и кампании, договоры и чеки. У каждого специалиста свой кабинет, данные общие и обновляются у всех сразу.

**Стек:** React + Vite + Tailwind, база и файлы — Supabase (Postgres, Auth, Storage, Realtime).

## Что внутри

- **Обзор** — воронка блогеров по этапам, выходы этого месяца, комиссия по кампаниям и список «что сделать»: кому пора напомнить о себе, у кого наступил срок следующего шага, у кого не уточнён статус самозанятого или ИП, какие выходы без erid.
- **Блогеры** — таблица и канбан-доска. Статус меняется прямо в строке или перетаскиванием карточки. Клик по строке открывает карточку блогера:
  - дорожка этапов (Поиск → Переговоры → Документы → Оплата → Выход) — статус меняется одним кликом;
  - **Работа** — комментарии и история: кто и когда сменил статус, что загрузил;
  - **Данные** — все поля: охваты, цена, контакт, правовой статус, РКН, ответственный, теги;
  - **Интеграции** — выходы блогера со своими статусами, erid, промокодом, охватом по факту;
  - **Документы** — загрузка договоров, актов, чеков, скринов (или ссылок на Яндекс Диск).
- **Импорт из Excel** — загружаете таблицу, сайт сам находит колонки со ссылками и никами, подписчиками, охватами, ценой. Кто уже есть в базе — пропускается.
- **Интеграции** — все выходы с фильтрами по кампании, этапу, периоду и маркировке; итоги по деньгам и охвату.
- **Клиенты и кампании** — бюджет, комиссия, предоплата, сколько бюджета уже ушло на блогеров.
- **Документы** — все файлы со всех карточек в одном месте.
- **Команда** — админ открывает доступ новым специалистам и назначает роли.

## Запуск за 15 минут

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватит).
2. **SQL Editor → New query** → вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) → **Run**. Создадутся таблицы, права доступа и хранилище для документов. Скрипт можно запускать повторно.
3. Чтобы загрузить блогеров из ваших таблиц — так же выполните `seed.sql` (он не лежит в репозитории, потому что репозиторий публичный). Либо загрузите таблицы через кнопку «Импорт из Excel» на сайте.
4. **Authentication → Sign In / Providers → Email**: для быстрого старта можно выключить *Confirm email*, чтобы коллеги входили сразу после регистрации.
5. **Project Settings → API**: скопируйте *Project URL* и *anon public key*.

### 2. Сайт на Vercel

1. [vercel.com](https://vercel.com) → **Add New → Project** → импортируйте этот репозиторий.
2. В **Environment Variables** добавьте:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
3. **Deploy**. Каждый пуш в `main` будет обновлять сайт автоматически.
4. В Supabase → **Authentication → URL Configuration** укажите адрес сайта в *Site URL*, чтобы письма подтверждения вели на него.

### 3. Первый вход

- **Первый, кто зарегистрируется, станет админом** — зарегистрируйтесь сами сразу после деплоя.
- Остальные регистрируются по ссылке на сайт и попадают в «Команда → Ждут доступа». Пока админ не откроет доступ, они не видят никаких данных.

## Локальная разработка

```bash
cp .env.example .env   # вписать URL и ключ Supabase
npm install
npm run dev
```

## Как устроены права

- Видеть и менять данные могут только активные специалисты (проверка на стороне базы — RLS, а не только в интерфейсе).
- Роль и доступ меняет только админ.
- Смена статуса блогера или интеграции автоматически записывается в историю с автором.
- Файлы лежат в приватном хранилище; скачивание — по временной ссылке.

## Статусы

| Этап | Статусы |
| --- | --- |
| Поиск | Новый, Написали, Жду ответ |
| Переговоры | Переговоры, Согласовано |
| Документы | Жду реквизиты, Жду договор, Жду подпись |
| Оплата | На оплате, Оплачено |
| Выход | Вышел, Закрыт |
| Стоп | Отказ, Чёрный список |

Список задан в `src/lib/constants.ts` и в функции `valid_status` в `supabase/schema.sql` — менять нужно в обоих местах.
