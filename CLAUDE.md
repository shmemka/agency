# Сверка - заметки для Claude

## Ветки
- Исходный код - в ветке `main`. Ветка `gh-pages` - только собранный сайт, её целиком перезаписывает `npm run deploy`. Если сессия открылась на `gh-pages`, работай в `main` (например, через `git worktree add <папка> origin/main`).

## После каждого изменения - всегда, без отдельного вопроса
1. `npm run build` - сборка должна пройти без ошибок.
2. Коммит в `main` и `git push origin main`.
3. `npm run deploy` - публикует сайт на https://shmemka.github.io/agency/

Это постоянное разрешение владельца проекта. Спрашивать перед push в `main` и публикацией не нужно.

Если изменение затрагивает базу, новая миграция кладётся в `supabase/migrations/` со следующим номером. Выполнить её в Supabase (SQL Editor) может только владелец - напомни ему об этом и скажи, в каком порядке с публикацией её запускать.

## Дизайн интерфейса
Владельцу нравится результат редизайна «Настроек кабинета» (`src/pages/Settings.tsx`) - это эталон. Правила собраны по методу unslop (github.com/heydamir/unslop, автор Damir Sokolovsky, CC BY 4.0) и по решениям владельца. Применяй их к любому новому или изменённому экрану.

Главный принцип: оболочка спокойная, а цвет и внимание достаются одному-двум важным местам экрана.

- **Цвет.** Поверхности нейтральные: `bg-canvas`, `bg-surface`, `bg-soft`. У текста три роли: `text-ink` - основной, `text-muted` - пояснения и подсказки, которые нужно прочитать, `text-faint` - только мелкая мета и единицы измерения. Лайм - один акцент на экран: главное действие или «Улучшить». `bad` - только для ошибок и необратимых действий, `leaf` - для успеха. Без градиентов, свечения, цветных теней и цветных рамок; линии - `line` / `bg-line`.
- **Иконки.** Только lucide, `strokeWidth={1.5}`, обычно `size-4`, цвет как у текста рядом. Без эмодзи. Иконка ставится, только если помогает понять действие.
- **Отступы.** Сетка 4px. Карточки `Card` (`p-5 sm:p-6`), между карточками `gap-3`. Внутри группы промежутки меньше, чем между группами. У одинаковых вещей одинаковые размеры: строки одной высоты, поля одной ширины в ряду, без полупустых рядов. Произвольные значения вроде `mt-[13px]` - только если они что-то точно центрируют.
- **Шрифт.** Веса 400 и 500, иерархия - размером и цветом, а не жирностью. Без капса с разрядкой и без курсива. На мелком тексте без отрицательного межбуквенного интервала. Исключение - цифры дат в задачах (`DuePicker`), это решение владельца.
- **Числа.** Всегда `num` (`tabular-nums`) и один формат: тысячи через пробел (`Intl.NumberFormat('ru-RU')`). Единица стоит рядом с числом или суффиксом внутри поля: «30 %», «30 дн.», «2 400 000 ₽». Пример - `NumberInput` в `Settings.tsx`.
- **Тексты.** Только короткие тире (-). Заголовки, подписи, кнопки и подсказки без точки в конце и без восклицательных знаков. Пишем коротко и конкретно, одно предложение там, где можно. Заголовок - название страницы, без приветствий. Подзаголовок нужен, только если сообщает что-то новое.
- **Без повторов.** Одна и та же информация не показывается дважды рядом. Блок без действия (например, «покинуть нельзя») ведёт туда, где проблему решают: кнопка-ссылка «Открыть команду».
- **Формы.** Подпись над полем, подсказка под ним. Кнопки «Сохранить» и «Отменить» появляются только после изменений (`SaveBar` в `Settings.tsx`); серых неактивных «Сохранить» нет. Enter сохраняет (`submitOnEnter`). Поля одной темы собраны в группу с коротким заголовком; группы разделены тонкой линией.
- **Необратимое.** Отдельная карточка в самом низу. Каждое действие - строка: слева заголовок и одно предложение о последствиях, справа кнопка (`variant="danger"` с `bg-bad/8`); на телефоне кнопка под текстом. Удаление подтверждается вводом названия, а в окне цифрами показано, что пропадёт.
- **Скругления.** `rounded-card` у карточек, `rounded-inner` у вложенных блоков, кнопки и плашки - `rounded-full`, поля - `rounded-2xl`. Новые радиусы не вводить.
- **Движение.** Только классы из `index.css` (`fade`, `rise`, `pop`, `stagger`, `appear`, `bump`). Переходы - только по `color`, `background`, `transform` и `opacity`, с перечислением свойств. Без `transition-all`, `hover:scale` у карточек и бесконечных `animate-pulse`.

### Порядок работы над заметным изменением интерфейса
1. **Посмотреть экран.** Временно поднять превью на моках: `vite.mock.config.ts` с алиасами `auth/AuthProvider` и `lib/data` на `src/_mock/*`, плюс `preview.html` и `src/_preview.tsx`. Снять скриншоты Playwright на компьютере (1280 px) и на телефоне (`devices['iPhone 13']`).
2. **Для редизайна** сначала написать аудит (что не так и где) и план. Показать владельцу и дождаться ответа. Мелкие правки по прямой просьбе делаются сразу.
3. **Сделать правки** и снова снять скриншоты, сверить с аудитом, проверить телефон.
4. **Удалить мок-файлы,** затем выполнить шаги из раздела «После каждого изменения».
